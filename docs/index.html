ctpbee_

面向中国期货市场的交易与行情引擎 —— CTP 回调之上的一层干净抽象： 事件驱动的策略开发、本地持仓管理、Redis 订单中继、内置回测、独立工具注册原语。

01 / QUICKSTART

01快速开始

pip 安装后写一个最小策略：在合约回报时订阅目标合约，逐笔接收行情。

hello_ctpbee.py
from ctpbee import CtpBee, CtpbeeApi
from ctpbee.constant import TickData, ContractData

class Main(CtpbeeApi):
    def on_tick(self, tick: TickData):          # 每笔行情
        print(tick.local_symbol, tick.last_price)

    def on_contract(self, contract: ContractData):
        # 登录后合约信息全量推送, 适合在此订阅
        if contract.symbol == "ag2612":
            self.action.subscribe(contract.local_symbol)

app = CtpBee("market", __name__, refresh=True)
app.config.from_json("config.json")
app.add_extension(Main("hello"))
app.start(log_output=True)

完整示例见仓库 examples/：login.py(ATR 策略实盘入口)、 kline.py(K 线注入，依赖 ctpbee_kline)、run_arb.py(跨期套利)、 backtest/(回测)、openctp/(子账户分发)。 示例中的合约代码与账号配置请按自己的环境更新。

02 / CONFIG

02配置

JSON 文件为基础，环境变量可覆盖——部署时凭据与参数不必进代码库。

键说明
CONNECT_INFO柜台连接(userid / password / brokerid / md_address / td_address / appid / auth_code)
INTERFACE接口:ctp / local 等，默认 ctp
MD_FUNC / TD_FUNC是否启用行情 / 交易功能
SUBSCRIBE_CONTRACT合约列表，初始订阅
INSTRUMENT_INDEPEND按策略 instrument_set 过滤行情(集合需含 local_symbol 形式)
SLIPPAGE_*BUY / SELL / SHORT / COVER 四向滑点，默认 0
PATTERNreal(实盘) / looper(回测)
RD_CLIENT_*DISPATCHER 模式 Redis 地址/端口/库

环境变量

from_envvars 读取 CTPBEE_ 前缀的环境变量，值按 JSON 解析 (布尔/数字/列表/字典均可，CONNECT_INFO 可整体传 JSON 字符串)，解析失败保留原始字符串：

env.sh
export CTPBEE_TD_FUNC=false
export CTPBEE_RD_CLIENT_PORT=6379
export CTPBEE_CONNECT_INFO='{"userid": "001", "password": "***", ...}'

# 推荐优先级: 文件值 < 环境变量
app.config.from_json("config.json")
app.config.from_envvars()          # prefix="CTPBEE_", silent=True

其他导入方式：from_mapping(dict)、from_object(obj)(取全大写属性)、 from_pyfile(file);统一过滤非大写键。

03 / ARCHITECTURE

03架构

CTP 的 C++ 回调在最底层，向上只经一次信号分发——每个环节都可替换、可模拟、可测试。

C++ CTP 回调md_api / td_api · interface/{ctp, ctp_rohon, ctp_mini}
数据对象构造TickData / OrderData / TradeData … · 时间戳快速构造(ActionDay 缓存)
blinker 信号common_signals(tick/bar/timer) + 每应用信号(order/trade/…)
Recorder 数据中心@call 装饰分发 · 最新行情/报单/成交簿记 · 查询接口
本地持仓盈亏纯函数 · 输入未变跳过重算
Toolstool_register 钩子 · K 线聚合等
你的策略CtpbeeApi 子类 · on_tick / on_trade …

工作模式

  • Mode.API —— 常规模式，策略在本进程内直接收到行情与交易回报
  • Mode.DISPATCHER —— Redis 中继模式：行情/订单经 TICK_KERNEL / ORDER_UP_KERNEL / ORDER_DOWN_KERNEL 通道与外部进程交互(键名可配)； 断线自动重连、行情异步入队、发布失败不阻断回调链

数据查询

策略内经 self.recorder 取最新状态：get_tick / get_last_price / get_order / get_trade / get_contract 等;账户初始化完成后 on_init 触发一次。

04 / STRATEGY API

04策略回调

继承 CtpbeeApi，重写你关心的回调。

回调触发
on_tick(tick)每笔行情(须重写，基类为 NotImplemented)
on_bar(bar)K 线(需注入 K 线 Tool，如 ctpbee_kline)
on_order(order) / on_trade(trade)报单状态 / 成交回报
on_position / on_account持仓与账户回报
on_contract(contract)合约信息(登录后全量推送，适合在此订阅)
on_init(init)账户初始化完成(仅一次)
on_realtime()定时器触发(配合 timer 事件)

不想写完整类骨架时可用路由装饰器:

route.py
strategy = Main("hello")

@strategy.route(handler="tick")      # "tick" / "order" / "trade" / ...
def handle_tick(self, tick):
    print(tick.last_price)

instrument_set 配合 INSTRUMENT_INDEPEND 按合约过滤行情， 集合内请放 local_symbol 形式(如 "ag2612.SHFE")。

05 / ACTION

05下单接口

四个语义化入口，平仓自动按今昨持仓拆分——命名按「方向_开平」理解，别被 buy_close 字面意思带偏。

接口语义底层
action.buy_open(price, volume, origin)多头开仓buy
action.buy_close(...)平多头(卖出平仓，自动拆平今/平昨)cover
action.sell_open(...)空头开仓short
action.sell_close(...)平空头(买入平仓)sell
action.cancel(order_id, origin)撤单—

origin 传触发行的行情/K 线对象，用于提取合约与交易所； 可加 price_type=OrderType.FOK 等参数；价格会叠加对应方向的 SLIPPAGE_* 配置。 上期所平仓会按持仓自动拆分平今/平昨报单。

06 / TOOL_REGISTER

06Tool 注册原语STANDALONE

ctpbee/tool_register.py 只依赖标准库——其他项目可以单独引入，ctpbee 的 Tool 体系只是它的第一个用户。

tool_register_demo.py
from ctpbee.tool_register import tool_register, register_tool_hook

class Calc:                          # 任意类, 无需继承任何基类
    @tool_register("tick")            # 键任意可哈希: 字符串/枚举/None
    def on_tick(self, tick):
        return tick.last_price          # 返回值喂给订阅者

c = Calc()
register_tool_hook(c, "tick", print)   # 订阅(注册序 + 去重)
# unregister_tool_hook(c, "tick", print)  退订
  • 契约: 回调在方法返回后触发，收到的是方法的返回值
  • 隔离: 单个回调异常被捕获并节流告警——不会沿宿主方法向上传播打断行情链
  • 快照迭代: 回调执行中注册/退订下一轮生效，不崩溃
  • ctpbee 内：基类 Tool 五个回调默认挂接，subscribe()/add_func() 开箱即用； K 线等工具经 app.with_tools(tool) 注入

08 / PERFORMANCE

08性能与稳定性

为全市场订阅设计——数千合约并发时，Python 侧每 tick 的固定开销在微秒级。

0.3 µs
行情时间戳构造(ActionDay 缓存)
3.1 µs
TickData 对象构造(批量初始化)
0.1 µs
同价 tick 持仓盈亏(纯函数跳过)
~3.4 µs
每 tick Python 固定成本合计

参考量级 · Windows / Python 3.13

稳定性设计

  • 回调隔离: tool_register 钩子、DISPATCHER 发布的单点异常被捕获并节流告警，不沿 CTP 回调链向上传播
  • 中继自愈: DISPATCHER 断线 5s 退避重连；行情异步入队(有界，满丢最旧)
  • 盈亏纯函数: 价格/持仓/均价/乘数输入未变即跳过重算；外部改动后同价 tick 也会重算，不留陈旧盈亏
  • frozen 保护: 数据对象属性仅允许下划线调用方写入，防策略层误改行情数据
  • 序列化自洽: DDDR encode→parse 往返可用，键嗅探兼容手搓 dict 载荷
09 / CAVEATS

09注意事项

  • 交易日历有边界: 内置日历目前覆盖至 2026-12-31，跨年前后请更新 ctpbee/date.py，否则时段判断与交易日推导将失效
  • 行情时间戳为 100ms 量化: 历史契约，依赖毫秒精度的策略需知悉
  • 大商所时间戳用本机日期: DCE 的 ActionDay 是交易日，引擎用 date.today() 拼接——请在北京时区主机上运行
  • 涨跌停单边行情: CTP 无价档位的哨兵值(极大浮点数)会原样进入 tick 字段，消费端自行过滤
  • exchange 类型兼容: 数据对象同时接受字符串与枚举；自定义构造时建议统一用 Exchange 枚举
  • INSTRUMENT_INDEPEND: 过滤比较 local_symbol(如 ag2612.SHFE),策略的 instrument_set 需放同形式(或在 on_contract 中补全)
